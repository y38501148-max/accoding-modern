# 页内代码复核（1.8.0）

在「班级」中读取比赛，打开「代码复核」，在「复核设置」填写管理员提供的共享只读令牌。页面按本地名册与 OJ 榜单唯一匹配的用户筛选提交；匹配冲突或缺失的同学显示待核对。点击「查看复核」可在 OJ 内查看源码、前一版本、差异、规则数值和模型解释。提交代码页也提供「代码复核」侧栏。

API 固定为 `https://muzermat.online:8443/oj-review-api/v1`。使用 `fetch` 与 `credentials: "omit"`，保留 `@grant none`。令牌只存在当前浏览器，不在发布脚本中。共享令牌拥有全库读取权限，本地班级筛选不构成服务端班级隔离。

「刷新结果」只查询数据库；不会触发模型任务。状态区分尚未采集、规则完成但未运行模型、排队、处理中、完成、失败、取消和过期。超过上下文预算而未调用模型的任务单列为「上下文不足，未运行模型」，不会显示普通「完成」。规则标签不能单独判定 AI 来源；规则未命中不能当作模型已复核。

人工记录绑定提交 ID 和源码 SHA-256，保存在本机。可导出筛选后的结果与标注，由管理员通过签名 CLI 导入集中记录。重跑模型不会覆盖人工记录。

查询每批不超过 250 个 ID。完成结果缓存最多 60 秒；显式刷新绕过缓存。未完成任务每 30 秒刷新。关闭面板、切班、换比赛会取消请求，且异步结果必须通过班级、比赛与请求代次检查才能展示。全部源码、引用和模型文字使用 `textContent` 或文本节点呈现。

## 验证

- `npm run check`：65 项单元与回归测试。
- 实际 OJ 页面至线上 API 的 CORS、鉴权、缺失状态验证通过。
- 实际班级列表验证：141 人名册对应 1,680 条提交（1 人待核对）；115 人名册对应 1,420 条提交。
- 注入延迟响应后切班，旧班级结果不会写入新班级视图。
- 实际提交页内的复核侧栏可读取源码、旧版本与差异。
- 已在实际提交页验证 ROG 本地模型结果、原文行号、替代解释和缺失上下文的显示。停止 worker 后查询仍可用，连续刷新不增加任务。

注释解释分别标明讲解、编号步骤、对答建议、模板／IDE 说明、题面复述、普通变量说明和注释掉的代码。类型本身不是 AI 来源结论。

模型选择源码行 ID，程序读取对应的不可变原文并由服务端再次校验，因此原文与行号可以核对。这个校验不证明模型解释正确：例如模型仍可能把被注释的 scanf 误称为输入防护，或错述相邻行的含义。解释与替代解释都需要人工结合当前代码和前一版本核验，不能作为已确认的事实或 AI 来源结论。


## 整场批次（1.9.0）

由 Mac 一次签名授权整场提交清单后，server3 自动补入任务并保存进度。默认全量规则检查，规则候选全部复核，未命中按题目和判题结果分层抽取 3%、最多 300 份。达到上限时实际抽样比例会更低；模型并发沿用现有设置。

当前班级面板新增候选、抽样、仅规则、未纳入批次的数量和筛选，单条详情显示批次名称、选入方式、是否复用任务。本批模型统计只计算本批选中提交，排队、待调度、失败和上下文不足分别显示。此前做过校准但本批未选中的提交仍可查看旧解释，其本批状态仍是“仅规则检查”。

插件读取、刷新和导出只查询结果。新建批次、恢复或重试需由 Mac 签名；Mac 离线后 server3 和 ROG 继续工作。批次暂停只停止补入新任务，已排队任务继续完成。

任务完成表示本批选中条目处理结束；上下文不足表示未执行模型，代码特征与模型解释均需结合题目和版本核对，不能直接作为作弊结论。
