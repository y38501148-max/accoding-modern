# 代码核查与查重

1.24.5 合并列表与详情读取，减少跨网往返，并在面板内复用已通过哈希验证的源码；人工结论与历史保持即时读取。见[加载修复与实测](review-loading-20261029.md)。

题面代码块中的已提供代码、通用输入输出、简单声明及可识别的固定几何公式不计入查重相似率；扣除后有效代码不足时不报相同。控制流、算法性数组更新和未识别的计算仍参与比较。列表和详情按当前班级的当前作者筛选，对照可来自外班，代码对和对照两栏显示双方姓名。保存权限验证材料随核查结果同步，公开的查重片段不会用作保存权限证明。

整场复核时自动查重，从 E 题开始（含 E），比较同场、同题、不同学生代码。A–D 题不参与，同一学生的多次提交不互相比较。选择班级后，对照仍可以来自本场其他班级。

相似率达到 95% 列为嫌疑代码。列表按两份提交合并，每对只显示一张卡，统计对数和涉及的提交数。先合并再分页；每份提交最多保留三位同学的对照。支持查看原文片段和完整代码。

展开卡片可填写「无抄袭 / 存疑 / 有抄袭」及理由。新记录默认不选结论。保存后保留助教姓名、时间和修改记录；其他助教已修改时，需要刷新记录再保存。无抄袭的记录从默认列表移走，在「全部核对状态」中查看。查重结论单独保存，不影响 AI 特征复核和规则评分。

当前支持 C / C++。比较前去掉空白、注释和预处理行，统一变量名，保留操作符、常量和字符串。少于 80 token 的代码、未完成评测、其他语言或无法解析的提交不参与比较。近似代码由指纹筛选后计算相似率，至少匹配 60 token。

源码与查重快照绑定。加载完整对照时核对双方的提交编号、作者、比赛、题目和源码哈希。读取无需验证身份，保存沿用现有复核权限。旧运行没有查重数据时显示未就绪。

已冻结源码的比赛可单独重算并上传查重，无需重跑 AI 复核；已有人工复核记录保留。未生成源码快照的旧比赛需先采集复核并同步。验收页的保存只在当前页面生效，刷新会重置。

# 代码复核 1.20.8

历史与配对代码对照默认展开，仅读取当前选中的一份。跨题引用按历史提交所属运行读取；缺少运行编号时从该提交的完整运行中查找，并核对提交 ID、作者、比赛、题目和源码哈希。成功对照在本次详情中缓存；单份读取失败显示重试及原提交入口，人工核查和草稿继续保留。


核查列表、详情、源码、人工历史与导出直接读取云端，不发送 Bearer，也不验证 OJ 账号或请求读取证明。长期成员画像、画像辅助分和后台刷新已停用。

默认选择 `publication_ready` 非 false 的最近一次完整运行，兼容未声明字段的历史运行。新运行上传中断时继续展示上次完整结果；没有完整版本时显示待同步。核查运行下拉可主动查看尚未发布完整的历史运行，并明确标为待同步。

新版名单默认显示「规则命中/未核查」「已核查为存疑」「已核查为AI」，分别计数；「全部代码状态」与「已核查为无AI」可查看人工排除记录。按 OJ 用户 ID 聚集，按题显示最后一份实际命中的代表提交。后续未命中提交不覆盖代表，每人题数不限。WA 只作历史对照。旧运行与旧人工记录保留，命名特征只在历史运行中可读，新版筛选和风险规则删除命名。

人工结论依次为「无 AI」「存疑」「有 AI」。未核查代码初始显示「请选择核查结论」，规则命中不预填人工结论，历史浏览器草稿仅恢复理由。保存需主动选结论、填写理由并点击按钮；沿用源码哈希、必填理由、修订冲突校验与请求幂等标识。存疑保存后留在复查队列。未知状态报格式错误，人工专属记录使用 `result:null` 与 `human_status`，不伪造机器判断。

v4 请求声明 `X-Review-State-Protocol: 2`。人工结论与理由可以立即编辑；仅点击保存时核实写入身份和三态协议能力。

列表显示评测结果、规则分与人工理由。详情展示同题前版（可含 WA）、较早命中和重复 AC 时间线、源码哈希、真实 token 增删量、解析不可靠提示及规则排除说明。跨题对照不作算法 diff，同题历史可翻阅逐行 diff。来源与 AI 使用仍由助教核实。


浏览器可导出 JSON 与 XLSX，均读取最新同源码人工反馈。当前核查表包含所选名单、最后命中代表、评测与版本、两种分值和三态；完整证据表通过授权分页接口加载全场已冻结源码身份、所有命中事实、WA 对照与完整人工历史。XLSX 含「嫌疑名单」「助教反馈历史」「完整证据与对照」三表，标识和理由保持文本，避免公式执行。筛选或班级切换会取消过时导出。

已保留 1.19.6 的直接站点、e1/e2/e3 与路径型 VPN、XLS/XLSX 导入、名册共享和成绩导出能力。

# 代码复核 1.18.9

代码状态统一为「规则未命中」「规则命中/未核查」「已核查为AI」「已核查为无AI」。代码复核名单只显示「规则命中/未核查」和「已核查为AI」。超过复核限额但实际命中的代码仍保持「规则命中/未核查」，默认名单不收录；助教判定为 AI 后进入名单，判定为无 AI 后从名单移除。班级列表按 OJ 用户 ID 聚集，同一用户的提交相邻；可按题目、特征及这两种状态筛选。人工结论同步给其他助教。没有人工结论时，规则命中只表示待核查，不表示已确认使用 AI。

完整规则命中和源码清单以所选完整发布运行为准；同步中的新运行不会取代默认完整结果，历史运行按其实际材料展示。

从「按题查看通过提交」选择「进入本题代码核查」打开独立的本题提交核查页面，不自动打开某位学生的详情。该名单列出本题尝试者的具体提交：有 AC 的每人取最新一次 AC，没有 AC 的每人取最近两次尝试；默认显示所有五种代码状态，供助教逐条核查。首页「代码复核」名单独立运行，只显示待核查命中和已核查为 AI。学生提交记录也可直接打开对应详情。

详情右上角显示代码状态。左侧为本次提交，右侧快照可用按钮翻阅：跨题码风变化显示对照提交的具体题目及源码，不标增删颜色；同题上次提交显示逐行 diff，本次增加行标绿、上次减少行标红。没有更早提交时不着色。顶部上一页、下一页按当前名单顺序翻阅；返回列表时保留滚动位置。源码读取失败时显示错误，不会把失败误判为没有更早提交。

源码读取和人工保存分别处理：读取无需凭证；保存保留实名身份核实、必填理由、修订冲突检查和幂等重试。写入身份尚未验证或保存失败时保留当前草稿。仅点击保存时，从 OJ 当前登录主页取得用户 ID 和姓名，验证本场三份未公开源码的写入能力。私有指纹使用 `sha256("oj-review-write-proof-v2\n" + code)`，只将 CRLF/CR 规范为 LF；公开源码哈希无法替代该证明。写会话按 OJ 用户和比赛隔离，最多 8 小时，优先存于油猴 GM 存储；无 GM 时仅留当前页面内存。401/403 清除匹配的写凭证并重新验证一次，重试沿用原请求 ID。

人工反馈按提交 ID 和源码 SHA-256 绑定，跨规则运行保留。保存必填理由；云端记录助教身份、时间、当时的原始规则判定和每次修订。其他助教刷新即可看到最新结论。冲突时要求先读取最新历史，不覆盖他人的修改。请求失败保留页面草稿，重试使用同一请求标识。历史浏览器备注会填入编辑框，须主动保存后上传。

源码始终校验冻结哈希。未命中提交的身份来自云端已签名的整场源码清单，源码按需从已登录 OJ 读取。无法读取或摘要不匹配时停止保存。更正结论不会修改学生提交的代码。

独立提交检查页仍提供逐行 diff：删除为红底 `-`，新增为绿底 `+`，未变化为普通背景，并同时显示前后行号。

规则系统已取消模型核查。完整历史的每份提交均执行全部规则，再按命中结果去重限额：每人每题保留最后一份实际命中的代码，每人题数不限。后续未命中提交不覆盖该代表，完整命中链和人工记录继续保留。

普通说明至少三行；语言知识、明确对答与答案包装单独识别，不受普通行数门槛限制。知识识别补充格式符、类型转换、内存分配释放、地址与字符串机制。交错题比对同一学生在整场快照内各题的源码，去除空白、注释和预处理行后 token 相似度至少 90% 时排除时间类嫌疑，保留独立注释或输入检查线索。只有空骨架的短程序不会触发排除。

导出包含当前列表和该比赛的完整助教反馈历史，便于后续复盘和规则优化。模型历史结果作为旧运行记录保留；新任务、重试、连接测试及对照入口均不能启动模型。


## 提交检查页（1.18.0）

打开 `/submission/提交ID` 直接进入检查页。顶部显示作者、题目、时间和评测结果，源码保留原始空白并显示行号，可复制代码。点击“加载前后差异”查询同一学生在同一题目中早于本次的最近提交（包含未通过提交），以红色删除、绿色新增和双行号展示；首次提交、完全相同、读取失败分别提示。查询失败不会被当作没有前版。

页底 AI 判定复用班级代码复核的人工结论、必填理由、冲突处理与云端历史。页面展示的源码需与云端清单哈希一致才允许保存；未纳入清单时源码和 diff 仍可查看，但不能保存判定。刷新历史保留理由草稿。


## 码风与罕见高级用法

“短时间大幅改写”仍限制为 360 秒（含边界），使用去空白、注释后的 token 增删比例，至少 30% 命中。“单题码风突变”按同一学生、同一道题前后提交的实际顺序比较，不设间隔上限；间隔超过 6 分钟也可以核查。纯格式化和变量、函数命名不计入新版单题码风风险。交错题高度匹配排除保持有效。

跨题对照按运行版本展示。v21 的同场配对模式见下节；旧版本继续显示其冻结事实，旧命名和纯排版门槛不作为新版规则。罕见高级用法检查非 I/O 内联函数、静态辅助函数、静态存储变量与函数指针；同题至少 20 名作者、使用率不超过 5% 才计为罕见。常见快读快写及其缓冲、游标和普通静态标量常量排除。所有命中是待人工核实的嫌疑线索。


## 历史命名规则（已删除）

1.18.2 和 1.18.3 曾检测变量、函数名长度、下划线和驼峰。自核查升级起，这些维度已从新候选、分值及画像风险中删除；旧运行仅保留其原始历史事实。

核查详情中的上一页、下一页会在保存后保持可用，并跳过已移出当前筛选名单的记录；一页记录核查完成后继续读取后续记录。右上角「查看该同学本次比赛提交」列出当前同学在本场比赛时间内的全部提交，包含所有题目、通过与未通过记录，支持按题筛选、分页和打开源码。返回当前核查时保留未保存理由及滚动位置。

云端历史若保存的是「OJ 用户编号」占位名称，页面按历史记录的助教账号 ID 读取其 OJ 资料并显示姓名；保留原始历史记录，不改动结论、理由或时间。新会话优先读取登录欢迎名称，缺失时读取该登录账号的资料页姓名。


## 同场固定配对（v21，界面 1.20.5）

仅 `cross_problem_style.comparison_mode=within_contest_non_overlapping_pair_v1` 使用此展示。同一作者、同一比赛中，两道题首次满足候选条件后固定为一对；每题最多属于一对，每对只核查首次锁定的 `selected_problem_id`，另一题后续方向反转只作观察。旧八场等既有运行保留原规则版本，不冒充已按 v21 重跑。

候选选择可比较内容组织更规范的一侧：两组内容变化方向一致，或一组内容变化与强排版佐证同向。内容包括说明性注释、可达非 I/O 辅助函数和可靠额外输入检查；相关排版合为一组佐证、零分，不独立触发。普通说明性注释的独立候选门槛仍为三行，短注释只有在配对组合证据中满足条件时参与比较。

详情说明同场配对编号、两道锁定题、唯一核查题、实际先后和内容变化方向。当前候选可能是较早提交，其配对对照也可能较晚；`previous` 只是旧协议的源码别名，不表示一定早于当前提交。当前实际比较的两份 `comparison_references` 是主要对照，源码仍校验固定身份与哈希，默认展开、仅当前选中的一份读取，成功结果复用缓存。全场 cohort 和配对前 population 只在折叠的技术详情保留，不展开为一长串源码请求，也不充作历史正常基线。同题已命中及 AC 时间线继续折叠保留人工状态、理由和源码链接；它们不会挤入主配对源码查看器，展开时间线也不自动读取代码。

## 单题码风比较取消时限（界面 1.20.6）

新运行的标签为「单题码风突变」，取消的仅是单题码风比较的 6 分钟限制；仍核验同一作者、同一道题和真实前后顺序，展示实际间隔。短时间大幅改写的 360 秒限制保持不变，两种规则分别处理。

筛选器同时保留旧「短时间码风突变」与新标签，不重命名旧运行的冻结事实。此次按新口径重核的范围仅两场 C4，其他八场保留原版本及旧标签。源码读取授权、按需对照、缓存、人工结论和修订历史均沿用现有机制。
